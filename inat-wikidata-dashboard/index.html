How this works — the semantic web plumbing
  1. iNaturalist REST API — fetches every observation in the project and collects the distinct taxa (scientific name, common name, photo, iNaturalist taxon ID).
  2. Comunica → QLever's Wikidata mirror — a fast SPARQL query resolves each scientific name to its Wikidata item (wdt:P225), and pulls cross-reference identifiers already stored on that item: GBIF (P846), iNaturalist taxon (P3151), Wikimedia Commons category (P373). This is the same reconciliation step as iNotListed, just run live in your browser instead of a Python CLI.
  3. Comunica → Wikidata Query Service — a second query checks, for every resolved item, whether an English, Japanese or Spanish Wikipedia sitelink exists (schema:about / schema:isPartOf). Anything missing is flagged — that's the "not listed" signal.
  4. Comunica → Plazi TreatmentBank (QLever) — a third query checks SynoSpecies's own QLever mirror of Plazi's taxonomic treatments (qlever.ld.plazi.org/sparql) for how many published treatments exist for each species (dwc:genus + dwc:species, joined to treatment:augmentsTaxonConcept / definesTaxonConcept). Plazi's coverage is the opposite shape of BHL's here — narrow (only taxa with a digitized taxonomic revision or original description) but, when present, precise: exact treatment title, DOI and author.
  5. BHL literature (on demand) — clicking "look up" on a row queries a personal experimental Biodiversity Heritage Library knowledge graph (koetai.semscape.org) with a federated SPARQL query: it starts in a named graph of BHL page metadata (Darwin Core terms), then reaches out via SERVICE to QLever for the Wikidata item and identifiers, and a nested SERVICE to WDQS for the Wikipedia sitelink — three data sources, one query, no data ever copied between them. Coverage in this graph is experimental and partial.
  6. Draft a stub (on demand) — click any red ✗ in the en/ja/es columns to draft a starting-point Wikipedia article for that language, in the spirit of taxonname-wpstubmaker: it fetches the taxon's ancestor chain from iNaturalist and its authorship/publication from GBIF, then fills in the language's species infobox ({{Speciesbox}} on English Wikipedia, {{Ficha de taxón}} on Spanish, {{生物分類表}} on Japanese) plus a lead sentence, reference and {{Taxonbar}}. These are drafts only — nothing is ever posted automatically; review formatting and notability before publishing.
  7. Roadmap — OpenStreetMap (observation localities / place alignment) and a richer Wikimedia Commons media panel are the next sources to wire into this dashboard.

Query timings for the current run are logged below the status line while it runs.
